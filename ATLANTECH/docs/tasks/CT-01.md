## 1. What is asked

Write the contract that fixes the common rules every port API endpoint follows (address prefix, time format, headers, idempotency, record version, error format and codes, pagination), get it reviewed and approved by the Frontend, Mobile and QA teams, and publish it as the single source of truth in a `contracts/` folder in PortHub. No application code: P1-A2 implements it.

**Done when:**

- [ ] `contracts/api-conventions.md` exists on PortHub `main`, marked **v1.0 · Approved**, with a change log.
- [ ] It covers: base path and versioning; time format; web and mobile headers; idempotency; record version (`updated_at DATETIME(6)`, returned as `version`) and 409; error format; status-code table; validation errors; pagination; one example per status code; a link to the error-code catalogue.
- [ ] `contracts/error-codes.md` lists every stable code known today with `message_key`, status, meaning and the task that introduced it.
- [ ] Every gap in section 7 is closed in the text (no "to be decided" left).
- [ ] The Frontend, Mobile and QA teams have approved it both in a team meeting and as GitHub reviews on the PortHub PR, and the approvers and date are recorded in the file header and in the decision log.
- [ ] `contracts/README.md` explains what the folder is, the versioning rule (change needs both sides, a decision-log entry and a new version) and lists both files.

**Out of scope:** implementing the rules in Laravel (P1-A2) · the OpenAPI file (CT-02, P1-A4) · sign-in flows (CT-03, CT-04) · sync event shapes (CT-07) · the contents of later error codes beyond those known today (each feature adds its own) · Arabic message texts (FR-GL-09, P2; post-MVP FW-11).

## 3. Design

No endpoints, tables or code. The deliverables are two documents in PortHub `contracts/`; their contents follow, with each decided choice marked by its question number (all answered, section 8).

### `contracts/api-conventions.md` outline

1. **Scope and version** — applies to every endpoint under `/api/v1` of the port API; v1.0; change log.
2. **Base path and versioning** — `/api/v1`; a breaking change means `/api/v2` alongside v1.
3. **Time** — ISO 8601 UTC on output with microseconds (`2026-10-28T10:15:04.123456Z`, Laravel's default); input must carry `Z` or an explicit offset and is converted to UTC, a value with no timezone → 422; the client converts for display (DEC-45; P1-A2 Q5, Q8).
4. **Headers** — web: session cookie + `X-XSRF-TOKEN` (Sanctum SPA); mobile: `Authorization: Bearer`, `X-App-Version`, `X-Device-Id`; JSON everywhere.
5. **Idempotency** — mobile writes carry `Idempotency-Key` (format, retention and replay behaviour: question 6).
6. **Record version** — every editable record returns `updated_at` (`DATETIME(6)`, ISO 8601 UTC with microseconds) as its version token; updates send it back; stale → 409 `VERSION_CONFLICT` with `current` (question 2, superseded 2026-10-28).
7. **Errors** — RFC 9457 body: `type`, `title`, `status`, `code`, `message_key`, `detail`, optional `errors` (422) and `current` (409); no stack traces or SQL (NFR-UX-4); English `detail`, translation keys always (question 8).
8. **Status codes** — table of every status the API may return, success and error (question 1).
9. **Error codes** — link to `contracts/error-codes.md` (question 4).
10. **Pagination** — `?page=&per_page=`; `{ "data": [...], "meta": { "page", "per_page", "total" } }`; default 25, maximum 100 (question 3).
11. **Examples** — one per status code.

### `contracts/error-codes.md` outline

Table: `code` (UPPER_SNAKE) · `message_key` (`errors.<area>.<name>`) · HTTP status · meaning · introduced by (task ID). Starts with the codes known today (`VALIDATION_FAILED`, `VERSION_CONFLICT`, `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND`, `ACCOUNT_DISABLED`, `APP_UPDATE_REQUIRED`, `LICENSE_READ_ONLY` (reserved), `PLAN_LIMIT_EXCEEDED` (reserved), `TOO_MANY_ATTEMPTS`, `IDEMPOTENCY_KEY_REUSED`, `SERVICE_UNAVAILABLE`, `SERVER_ERROR`, `SESSION_EXPIRED` 419 `errors.session_expired` "CSRF token missing or stale on a web request; fetch a new CSRF cookie and retry", introduced by P1-C1); each later task adds its own codes in its PR (minor version bump).
