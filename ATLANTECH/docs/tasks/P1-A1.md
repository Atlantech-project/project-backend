## 1. What is asked

Give the repository its final shape before any feature code: one folder per domain module, with the boundaries the architecture sets, and a Docker Compose stack that runs the Laravel API the way the port server will (PHP-FPM behind NGINX, MySQL 8, Redis), so every developer and the later CI and dev server start from the same environment.

**Done when:**

- [ ] `docker compose up -d` in `ATLANTECH/` starts `mysql` (8.4) and `redis`, both healthy; the app served by Herd runs `php artisan migrate` against them and reaches Redis.
- [ ] `docker compose --profile server up -d --build` also starts `app` (PHP 8.4-FPM) and `nginx`, and `http://localhost:8000/up` returns 200 through NGINX.
- [ ] `app/Modules/` holds one folder per domain module named in the backend architecture, plus the shared kernel, each registered automatically.
- [ ] Pest architecture tests enforce the module rules (shared kernel depends on no module; dependencies run one way only; no cycles).
- [ ] `php artisan test` passes under Herd and inside the `app` container.

**Out of scope:** `/api/v1`, error format, pagination (P1-A2) · CI pipeline (P1-A3) · OpenAPI file (P1-A4) · tables and migrations (P1-B1 onward) · Central SaaS app and DB (DEC-56: future work; P1-B7 later) · Reverb WebSocket server (P5-N2) · unprefixed Redis connection for AI jobs (P3-I1) · BAPLIE and model volumes, worker supervision, TLS 1.3 certificates (P3-H1, P6-R6) · shared dev server (DEC-47, Sprint 2).

## 3. Design

### Endpoints

None new. `/up` (Laravel health route, already registered) is used as the NGINX and container health check.

### Data

- No tables or migrations. `.env.example` points `DB_HOST` and `REDIS_HOST` at the Compose services.
- No enums.

### Modules

`app/Modules/<Module>/` under the existing `App\` namespace, one service provider per module discovered automatically, so a module can later register its routes, policies and listeners from its own folder. Proposed folders, from the architecture:

| Group | Modules |
| --- | --- |
| Shared kernel | `Shared` |
| Access and licence | `Access`, `License` |
| Master data and yard | `MasterData`, `Yard` |
| Vessel call flow | `Berthing`, `Baplie`, `Environment`, `Recommendation`, `Plan` |
| Field execution and learning | `Dispatch`, `Execution`, `Learning` |
| Integration | `AiBridge`, `Realtime` (SSE, WebSocket, notifications) |

Dependency direction, checked by Pest `arch()` tests in `tests/Unit/Modules/ModuleArchitectureTest.php`. Layers, earliest first; a module may use earlier layers, never later layers or its peers in the same layer:

1. `Shared` (uses no module) · 2. `Access` · 3. `License` · 4. `MasterData` · 5. `Environment`, `Berthing` · 6. `Baplie` · 7. `Recommendation` · 8. `Plan` · 9. `Yard`, `Dispatch` · 10. `Execution` · 11. `Learning`

Integration modules `AiBridge` and `Realtime` use only `Shared`; any other module may use them (step 2 change, see section 7). A test also fails when a folder in `app/Modules` is not placed in these rules, so a new module is placed on purpose.

### Containers

| Service | Image | Notes |
| --- | --- | --- |
| `app` | `php:8.4-fpm` + `Dockerfile` | Extensions: pdo_mysql, redis, intl, bcmath, pcntl, zip, opcache; Composer; runs as a non-root user; code mounted for development |
| `nginx` | `nginx:1.27-alpine` | Port 8000 → PHP-FPM; health check on `/up`; plain HTTP locally (TLS is P6-R6) |
| `mysql` | `mysql:8.4` (kept) | Named volume kept; health check |
| `redis` | `redis:7-alpine` | AOF `appendfsync everysec` (DEC-11 recommendation, development only until DEC-11 closes); health check |
| `phpmyadmin` | kept | Moved under a `tools` profile so it starts only when asked |

All services restart unless stopped (NFR-REL-1); MySQL 3306 and Redis 6379 stay published for Herd users and the AI team's local workers.

**Daily development (answer 2):** Herd serves the app with its own NGINX and PHP 8.4 at `http://atlantech.test`; `docker compose up -d` starts only `mysql` and `redis`. The `app` and `nginx` containers sit in a `server` profile (`docker compose --profile server up -d`) so the port-server shape exists for CI (P1-A3), the dev server (DEC-47) and deployment, without being needed every day (answer 5).
