## 1. What is asked

"Record every change together with who made it, in the same step as the change itself, and also record refused attempts. Done when no change can be saved without its audit entry." (`roadmap/roadmap-tasks.json:654-662`). Task row: `backend/atlantech_backend_tasks.md:71`, ref AIBD-025.

**Done when:**

- [ ] A write and its `audit_logs` row are saved in one transaction: if either fails, neither is stored.
- [ ] The audit service refuses to write a row outside a transaction, so a change cannot be saved with its audit row "later".
- [ ] A refused request is written as `REJECTED_ATTEMPT` with the same `after_state` shape as today (`{route, status, code, reason, username}`) and survives the rollback of the refused write.
- [ ] `actor_id` is NULL for the system / a worker, and is never left NULL by forgetting it (the parameter is required).
- [ ] CREATE rows carry no `before_state`, DELETE rows no `after_state` (`chk_al_states`), UPDATE rows carry only the changed fields, and no secret (`password_hash`, anything in the model's `$hidden`) is stored.
- [ ] `audit_logs` rows cannot be updated or deleted through Eloquent (NFR-SEC-6, model safeguard).
- [ ] `SignInService::recordRejectedAttempt` becomes a thin call into the service, so every existing caller and test (web sign-in, password gate, P2-D1 `AccessRefusal`, the mobile and seeder branches) keeps working unchanged.
- [ ] The hand-over list for P2-D1 and the password gate is written (section 6).

**Out of scope:** browsing the log (P2-F8) · role policies and `AccessRefusal` itself (P2-D1) · the write chain order (P2-D2) · the SM-4 transition service (P3-G2) · the platform audit log `platform_audit_log` of the SaaS database (P7-S6) · database privileges for the application account and triggers (deployment; see Q3).

## 3. Design

### Endpoints

None.

### Data

- Table `audit_logs`: written by the Backend only (CT-15 `contracts/ATLANTECH_Contracts.md:1044`). No migration, no enum change.
- Class `App\Modules\Shared\Audit\AuditService` (Shared module: every module may use it):
  - `transaction(Closure $write): mixed` runs the write and its audit calls in `DB::transaction`.
  - `record(AuditLogAction $action, string $entityType, ?int $entityId, ?int $actorId, ?array $before, ?array $after): AuditLog` generic writer (STATUS_CHANGE, SAFETY_EXCEPTION, later callers). Throws `LogicException` when `DB::transactionLevel() === 0`.
  - `recordCreated(Model $model, ?int $actorId)`, `recordUpdated(Model $model, ?int $actorId)` (after `save()`; before from `getPrevious()`, after from `getChanges()`; no row when nothing changed), `recordDeleted(Model $model, ?int $actorId)`. `entity_type` = `$model->getTable()`.
  - `rejectedAttempt(string $route, ErrorCode $code, string $reason, ?int $actorId, ?string $username, string $entityType = 'users', ?int $entityId = null): AuditLog` opens its own top-level transaction. It must be called after the refused write has rolled back, otherwise the row would roll back with it.
- `actorId` has no default value: the caller states `null` for the system.
- Redaction: attributes in the model's `$hidden` and `password`/`password_hash` are dropped from every state.
- `AuditLog` model: `updating` and `deleting` events and a builder that refuses `update()` / `delete()` throw (NFR-SEC-6 model safeguard).

### Behaviour

- Write chain steps: none; this service is what the write chain's "audit" step (P2-D2) and every later write call.
- Transaction boundary: caller's `AuditService::transaction()`; `record*` joins it (savepoint). Refusals: own transaction after the failed write.
- Audit rows: this task is the audit row writer.
- Licence mode: not applicable (no endpoint). Refusals caused by 423 are audited like any other refusal (the caller passes `ErrorCode::LicenseReadOnly`).
- Events and messages: none.

## 6. Impact on other backend work

- **P2-D1** (`claude/p2-d1-role-policies-6d2e9a`, unmerged, not edited here) must change when this PR merges: `app/Modules/Access/Services/AccessRefusal.php`: replace `SignInService $signIn` by `AuditService $audit` and call `$this->audit->rejectedAttempt($request->method().' /'.$request->path(), ErrorCode::Forbidden, $reason->value, $user->id, $user->username)`; fix its docblock; any D1 test that fakes `SignInService::recordRejectedAttempt`. Until then nothing breaks, because the old method stays and delegates.
- **Password gate and sign-in** (`EnsureAccountUsable::audit()`, `ChangePasswordRequest::failedValidation()`, `SignInService::refuse()`): switch to `AuditService::rejectedAttempt`, then delete `SignInService::recordRejectedAttempt`. Branches `p1-c-mobile-signin`, `p1-b6-seeders`, `p2-d2-write-chain` all call the old method today; delete it in one follow-up commit after all of them merge.
- **P2-D2** (write chain): the audit step calls `AuditService::transaction()` and `record*`; refused chain steps call `rejectedAttempt`.
- **P2-E1, P2-F1 to F5, P3-G2**: use `recordCreated/Updated/Deleted` / `record(StatusChange, ...)` inside `transaction()`.
- Must not break: the N6 `after_state` keys and the ordering of the refused row relative to the rollback.
