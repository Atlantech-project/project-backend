## 1. What is asked

"Create the data model for every table with its relations, and one fixed list of allowed values for every status column so all code uses the same status names. Done when every table can be read and written through the model layer" (`roadmap/roadmap-tasks.json:528-536`; `backend/atlantech_backend_tasks.md:45`).

Today there are no domain models: each of the 15 folders in `app/Modules/` holds only its service provider, and `app/Models/User.php` is Laravel's default (`email`, `password`), which does not match the `users` table (`username`, `password_hash`, no email; DEC-35).

**Done when** (each line is checkable by a test or a demo):

- [ ] Every one of the 92 contract tables has one model in its module (section 3 map); a guard test fails if a table has no model or a model points at no table.
- [ ] Every table can be written and read back through its model (one test per model, with the shape in Q7).
- [ ] Every relation the module rules allow is defined, and the relation tests load it.
- [ ] One PHP enum per ENUM value set in scope (Q3), backed by the exact SQL values; each model casts its ENUM columns to it; a guard test fails if an enum's values differ from the column's ENUM list.
- [ ] Timestamps match each table (`created_at` / `updated_at` / neither); the version token `updated_at` is read with microseconds.
- [ ] Generated columns are read-only in the models; Backend-only and AI-owned columns are marked as the CT-15 rules say (Q6).
- [ ] `User` model fixed for DEC-35 (`username`, `password_hash`), with its factory and the seeder (Q5), so `migrate:fresh --seed` runs.
- [ ] `ModuleArchitectureTest` passes (no module uses a later module or a peer).
- [ ] `php artisan test` passes, Pint clean.

**Out of scope:** seed data and the demo port (P1-B6); the audit service and write chain (P2-D3, P2-D2); sign-in, Sanctum, `getAuthPassword()` use in a guard (P1-C1, P1-C3); generating `status-vocabulary.json` (CT-21 task, unless Q8 says otherwise); policies, scopes and services; endpoints.

Placements that follow from the rules, not from the meaning alone:
- `organization_units` sits in Access with the roles; its `terminal_id` stays a plain column there, and `Terminal::organizationUnit()` (MasterData → Access, allowed) gives the link.
- `ml_models` and `ml_model_versions` sit in MasterData, because `entry_window_proposals` and `solver_run_model_versions` (Recommendation) point at them and Learning comes after Recommendation.
- Part 1 results (`entry_window_proposals`, `feasible_windows`, …) sit in Recommendation, because they point at both Environment and Berthing, which are peers.

### Models

- One class per table in `app/Modules/<Module>/Models/`, singular name (CT-17 §2), `$table` set explicitly; created with `php artisan make:model`.
- Keys: 71 tables use `id`; tables with one non-`id` key (`pilot_profiles.user_id`, `pilot_rank_limits.pilot_rank`, …) set `$primaryKey`, `$incrementing`, `$keyType`; composite-key tables (`berth_terminals`, `recommendation_option_tugs`, …) follow Q4.
- Timestamps per table: `CREATED_AT` / `UPDATED_AT` constants set to `null` where a column is missing; `updated_at` cast with microseconds (`datetime:Y-m-d H:i:s.u` or `immutable_datetime`).
- Casts: ENUM columns to their PHP enum; JSON to `array`; booleans; decimals as strings (`decimal:n`) so money and sizes keep their precision; all datetimes UTC.
- Generated columns never written (left out of `$fillable`); AI-owned and Backend-only columns as Q6.
- Relations: `belongsTo` for every FK whose target model is in the same or an earlier module; `hasMany` / `hasOne` / `belongsToMany` only inside a module or from a later module to an earlier one (Q2).

### Enums

- One backed enum per distinct ENUM value set in scope (Q3), `string` backed, cases in TitleCase with the exact SQL value (`case YardRecGenerated = 'YARD_REC_GENERATED';`), as the CLAUDE.md rule and "SQL names only" read together (Q3).
- An enum lives in the earliest module that uses it, in `app/Modules/<Module>/Enums/` (e.g. `TerminalType` in MasterData, used by Yard and Recommendation).
- A guard test compares every enum's values with its column's ENUM list in `information_schema`, so a migration and an enum cannot drift apart; this also makes CT-21 safe to generate later.

### Behaviour

No endpoints, transactions or audit here (P2-D2, P2-D3). Models carry no business rules beyond casts and relations.
