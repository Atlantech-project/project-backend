## 1. What is asked

A user with a one-time password cannot reach anything until the password is changed (`roadmap/roadmap-tasks.json`, P1-C2; FR-AC-03). CT-03 is written in the same task, since it describes this flow.

**Done when:**

- [x] With `must_change_password`, signed-in routes answer 403 `PASSWORD_CHANGE_REQUIRED`, except `auth/me`, `auth/change-password` and logout.
- [x] `POST /api/v1/auth/change-password` saves the password, clears the flag and writes the audit row in one transaction, and answers 200 with the profile and a new session id.
- [x] A deactivated user gets 403 `ACCOUNT_DISABLED` on the next request and is signed out (FR-AC-10).
- [x] `POST /api/v1/auth/logout` ends the web session with 204 (the web part of P1-C4, moved here by Marwan).
- [x] OpenAPI, its PortHub copy and `contracts/auth-web.md` (CT-03) describe this.

**Out of scope:** revoking the mobile token on logout (the rest of P1-C4, needs P1-C3) · mobile sign-in (P1-C3) · resetting a password (P2-E1) · ending the user's other sessions after a change (Marwan: they stay open, 2026-10-31).

## 3. Design

### Endpoints

| Method and path | Role(s) and scope | Request | Success | Errors (code) |
| --- | --- | --- | --- | --- |
| `POST /api/v1/auth/change-password` | Any signed-in user | `{ current_password, new_password, new_password_confirmation }` | 200 profile, new session id | 401 · 403 `ACCOUNT_DISABLED` · 419 · 422 `VALIDATION_FAILED` · 429 `TOO_MANY_ATTEMPTS` |

### Data

- Writes `users.password_hash`, `must_change_password`; inserts `audit_logs` (`UPDATE`, never the password). No migration.

### Behaviour

- `EnsureAccountUsable` runs right after `auth:web` on every signed-in route: `is_active` first, then the gate.
- Throttle: 5 requests per minute per user, so a session cannot guess the current password.
