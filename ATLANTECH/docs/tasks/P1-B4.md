## 1. What is asked

Add the database rules that protect data quality, "allowed values, checks between columns and calculated columns, exactly as the design states. Done when invalid rows are refused by the database itself" (`roadmap/roadmap-tasks.json:566-574`).

The rules already exist: P1-B1 created every CHECK constraint and generated column with its table (lead's answer 1 in P1-B1, `docs/tasks/P1-B1.md:141,156`: "P1-B4 keeps the tests"). The live database has **129 CHECK constraints on 60 tables, 17 generated columns and 103 ENUM columns**, and runs in strict mode (`STRICT_TRANS_TABLES`; `config/database.php:60` `'strict' => true`). Today only 4 CHECKs and a few generated keys are exercised by `SchemaConstraintsTest` (8 tests). So this task proves, with a sample of each kind of rule (answers 1 and 2), that the database refuses a row that breaks it, and guards that all 129 rules stay in place by name.

**Done when** (each line is checkable by a test or a demo):

- [x] A sample of CHECK constraints (answer 1): at least one of each kind (range, cross-column, format/regex, state consistency, mutually exclusive) and at least one per module, about 12 to 15, each refused with that constraint's error when broken; a valid base row of each sampled table is accepted. *Proven: `DatabaseRulesTest` 17 sampled CHECKs (range, singleton, state consistency, mutually exclusive, cross-column order and limit, format, case-sensitive format, sum within capacity, conditional) covering Access, MasterData (vessels, berths), Yard (storage, slots), Baplie, Realtime (notifications), AiBridge (part1_runs), Learning (drift), Recommendation, Environment, Plan (`chk_pc_time`) and Shared (`chk_al_states`); the Execution tables have no CHECK; 16 base rows accepted.*
- [x] A guard test lists the 129 CHECK constraints **by name**, so removing or renaming any rule fails the suite. *Proven: `DatabaseRulesTest` "all 129 CHECK constraints of the design are in place by name".*
- [x] The three generated columns the task names compute the designed value: `*.active_key` (`recommendations`, `operational_plans`, `tide_constituent_sets`, `yard_runs`, `baplie_parse_runs`), `storage_facilities.available_capacity`, `drift_measurements.is_drifted`; a generated column cannot be written. *Proven: `DatabaseRulesTest` generated values (11 cases, incl. `tide_constituent_sets.active_key`); not writable: `SchemaConstraintsTest` (tide_constituent_sets).*
- [x] The 8 generated unique keys (`active_key`, `confirmed_key`, `champion_key`, `single_key`, `active_assignment_key`, `active_request_key`, `live_hash_key`, `active_code`) refuse a second active row and allow it once the first is no longer active. *Proven: `DatabaseRulesTest` 11 unique indexes, each refused then allowed once inactive (incl. `tide_constituent_sets.active_key`; `uq_org_unit_type_key` has no active state and proves the unique pair); `uq_ura_active` refused and allowed after the role ends in `SchemaConstraintsTest`.*
- [x] ENUMs: the app connection runs in strict mode, and 3 sample ENUM columns refuse a value outside their list (answer 2). *Proven: `DatabaseRulesTest` strict mode and 3 ENUM columns.*
- [x] `php artisan test` passes, Pint clean. *Proven: 113 passed (415 assertions, 92 s) after the review fixes, `composer lint` passed.*

**Out of scope:** a test for every one of the 129 CHECKs and every ENUM column (answers 1 and 2: a sample plus the name guard); `chk_yr_retry` (answer 3, proposed to the AI Team instead); models, factories and PHP enums (P1-B5); seed rows (P1-B6); rules the database cannot hold and the code enforces (each feature task, e.g. "a berth has at least one terminal", "w_edi fills NULL vessel columns only"); changing any rule's meaning (the design is the source; a rule that looks wrong is reported, not changed, unless section 8 says so).

## 3. Design

### Endpoints

None.

### Data

- No table, column or rule changes (F43 not added, answer 3).
- Tests only, in `tests/Feature/Database/` next to `SchemaConstraintsTest` (answer 5): extend it or add `DatabaseRulesTest.php` in the same folder; no new folder.
  - **Base rows:** one helper per sampled table that inserts a valid row (FK checks off, rolled back per test, as `SchemaConstraintsTest` does).
  - **CHECK sample:** a Pest dataset, constraint name → the override that breaks only that rule; the test expects `QueryException` with the constraint name.
  - **Guard:** the CHECK names in `information_schema` equal a fixed list of 129 names.
  - **Generated columns and keys:** expected values from the DDL expressions; a second active row refused, then allowed.
  - **ENUMs:** `@@session.sql_mode` contains `STRICT_TRANS_TABLES`; 3 columns refuse an unknown value.

Not applicable (database rules only).
