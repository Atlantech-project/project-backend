## 1. What is asked

The terminal's working speed over time, without overlapping periods; the AI uses it to estimate how long a vessel stays at berth (`backend/atlantech_backend_tasks.md:93`; roadmap: "Done when overlapping periods are refused").

**Done when** (each line is checkable by a test or a demo):

- [ ] List, create and edit the profiles of one terminal: `vessel_type_id` (null = the terminal default), `productivity_rate`, `rate_unit`, `fixed_overhead_minutes`, `valid_from`, `valid_to` (null = open).
- [ ] A period that overlaps another profile of the same terminal and the same `vessel_type_id` (the default is its own level) is refused with 422 `errors.productivity_profiles.overlap`, on create and update, including two requests at the same time. The edge day counts as overlap.
- [ ] `valid_to` before `valid_from` is 422; rate above 0; overhead 0 or more; `rate_unit` `MOVES_PER_HOUR` (container terminals); `terminal_id` and `terminal_type` are taken from the terminal and refused in the body.
- [ ] Only the terminal's Terminal Admin writes (`equipment.manage`, `terminal.scope`), and only for a container terminal (403 otherwise); office roles read, terminal roles only their own terminal; an inactive terminal is read-only for its users (409).
- [ ] `terminal_productivity_profiles` has `updated_at DATETIME(6)`; every update sends `version`; every write is audited; nothing is deleted.
- [ ] OpenAPI, `schema.sql`, PortHub copy; Pint and the full suite pass.

**Out of scope:** equipment and yard (P2-F4) · the AI service-time calculation (AI-052) · NCT profiles (non-container work, future) · deleting a profile.

## 3. Design

| Method and path | Ability | Request | Success | Errors |
| --- | --- | --- | --- | --- |
| `GET /terminals/{terminal}/productivity-profiles` | `port-state.read` + `terminal.scope` | page | 200 | 401 · 403 · 404 |
| `POST /terminals/{terminal}/productivity-profiles` | `equipment.manage` + `terminal.scope` | fields | 201 | 401 · 403 · 404 · 409 (inactive terminal) · 422 |
| `PUT /terminals/{terminal}/productivity-profiles/{terminalProductivityProfile}` | same + `version.token` | partial + `version` | 200 | 401 · 403 · 404 · 409 · 422 |

- A profile of another terminal in the path is 404 (scoped binding).
- Container check in the Form Request `authorize()`, through `AccessRefusal` (`role_not_allowed`, audited like other role refusals), so it comes before validation.
- Transaction: lock the terminal row, then (on update) `lockAndAssert` the profile, check the period and the overlap, save, audit.
- Migration: `updated_at DATETIME(6)`, as the other version-token columns. Backend-owned table the AI reads, so the labeler adds `ai-impact` (CT-17 section 6).
- Events: none (`ResourceKind` has no profile).
