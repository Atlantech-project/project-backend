## 1. What is asked

Build the shared base every endpoint uses: the `/api/v1` prefix, one RFC 9457 error format with stable `code` and `message_key`, one paging style for every list, message keys ready for translation, and all times stored and returned in UTC (`backend/atlantech_backend_tasks.md:32`; `roadmap/roadmap-tasks.json:454-462`: "Done when a sample endpoint shows each of these and follows the conventions contract (CT-01)").

**Done when** (each line is checkable by a test):

- [x] API routes live in `routes/api.php` and are served under `/api/v1`; `/up` is unchanged.
- [x] Every error on `/api/v1/*` is `application/problem+json` with `type`, `title`, `status`, `code`, `message_key`, `detail` (CT-01, `split/contracts/CT-01.md:19-35`); framework errors map to stable codes: 401 `UNAUTHENTICATED`, 403 `FORBIDDEN`, 404 `NOT_FOUND`, 405 `METHOD_NOT_ALLOWED`, 422 `VALIDATION_FAILED` (with `errors`), 429 `TOO_MANY_ATTEMPTS`, 500 `SERVER_ERROR`, 503 `SERVICE_UNAVAILABLE`.
- [x] A 500 never exposes a stack trace, SQL, class name or file path, even with `APP_DEBUG=true` (NFR-UX-4).
- [x] The stable codes `ACCOUNT_DISABLED` (403), `LICENSE_READ_ONLY` (423), `PLAN_LIMIT_EXCEEDED` (422), `VERSION_CONFLICT` (409) and `APP_UPDATE_REQUIRED` (426) exist in one catalogue (PHP enum) with status and `message_key`, and a domain exception renders each as a problem response, including extension members (`current` for 409, `min_app_version` for 426).
- [x] Every `message_key` resolves in `lang/en/errors.php`; `detail` is the English text of the key; a test fails if a catalogue code has no translation.
- [x] A list endpoint returns `{ "data": [...], "meta": { "page", "per_page", "total" } }`; `per_page` default 25, maximum 100; invalid `page` / `per_page` → 422 `VALIDATION_FAILED`.
- [x] App timezone and MySQL session are UTC; datetimes are returned as ISO 8601 with `Z` (format per question 5); a datetime input with an offset is stored as UTC (question 8).
- [x] Sample endpoints (test fixtures, question 4) prove each line above in Pest; Pint clean; module architecture test still passes.

**Out of scope:** OpenAPI file (P1-A4, CT-02, DEC-13) · web/mobile sign-in and the actual `ACCOUNT_DISABLED` check (P1-C1, P1-C3) · `GET /api/v1/system/info` (P1-C5) · write-chain order (P2-D2) · version-token check and 409 logic (P2-D4) · licence guard 423 and plan-limit service 422 (P2-D5; licensing deferred by DEC-54) · idempotency middleware (mobile sync, P5) · Arabic texts (FR-GL-09 P2; FW-11 at `backend/atlantech_backend_tasks.md:292`) · writing and approving the contract itself (CT-01 task) · CI (P1-A3).

## 3. Design

### Endpoints

No product endpoint. Routing base only, plus test-only sample routes (question 4).

| Method and path | Role(s) and scope | Request | Success | Errors (code) |
| --- | --- | --- | --- | --- |
| `GET /api/v1/__sample/items` (tests only) | none | `?page=&per_page=` | 200 `{data, meta{page, per_page, total}}`, items with a UTC datetime | 422 `VALIDATION_FAILED` |
| `GET /api/v1/__sample/problem/{code}` (tests only) | none | — | — | each catalogue code with its status and extension members |
| `GET /api/v1/__sample/boom` (tests only) | none | — | — | 500 `SERVER_ERROR`, no internals |
| `POST /api/v1/__sample/items` (tests only) | none | JSON with a datetime | 201, datetime echoed in UTC | 422 `VALIDATION_FAILED` with `errors` |

### Data

- Tables and columns: none read or written. No migrations.
- Enums: `App\Modules\Shared\Errors\ErrorCode` (string-backed, values `UPPER_SNAKE`), each case with `status()` and `messageKey()`. Initial cases (CT-01 plan Q4 list + question 6): `VALIDATION_FAILED` 422, `VERSION_CONFLICT` 409, `UNAUTHENTICATED` 401, `FORBIDDEN` 403, `NOT_FOUND` 404, `METHOD_NOT_ALLOWED` 405, `ACCOUNT_DISABLED` 403, `PASSWORD_CHANGE_REQUIRED` 403, `APP_UPDATE_REQUIRED` 426, `LICENSE_READ_ONLY` 423 (reserved), `PLAN_LIMIT_EXCEEDED` 422 (reserved), `TOO_MANY_ATTEMPTS` 429, `IDEMPOTENCY_KEY_REUSED` 422, `SERVICE_UNAVAILABLE` 503, `SERVER_ERROR` 500. Later tasks add cases in their own PRs.
- Rules enforced in code: every case has a translation (test); `per_page` 1..100, `page` ≥ 1.

### Shared pieces (all in `app/Modules/Shared/`, which depends on no other module)

- `Errors/ErrorCode.php` — the catalogue enum.
- `Errors/ApiProblemException.php` — domain exception: an `ErrorCode`, optional `detail` override or translation replacements, optional extension members (`current`, `min_app_version`, …).
- `Errors/ProblemRenderer.php` — called from `bootstrap/app.php` `withExceptions()`; for `api/*` requests turns `ApiProblemException` and framework exceptions (`AuthenticationException`, `AuthorizationException` / `AccessDeniedHttpException`, `ModelNotFoundException` / `NotFoundHttpException`, `MethodNotAllowedHttpException`, `ValidationException`, `ThrottleRequestsException`, maintenance 503, any other `HttpException` by status, any other `Throwable` → 500) into the RFC 9457 body; `Content-Type: application/problem+json`; `type` = `https://atlantech.io/errors/<kebab-code>` (question 7); `title` = short English title; `detail` = `__(message_key)`; never trace or SQL; exceptions still reported to the log as today.
- `Http/Pagination/PageRequest` (or a trait for FormRequests) — validates `page`, `per_page`; defaults 25 / max 100.
- `Http/Resources/PaginatedCollection.php` — base `ResourceCollection` overriding `paginationInformation()` so every list returns exactly `meta: {page, per_page, total}` and no `links` (question 3).
- Datetimes: app timezone `UTC` and MySQL `+00:00` already set (asserted by a test); JSON format per question 5; an input rule / cast that accepts ISO 8601 with `Z` or an offset and stores UTC (question 8).
- `lang/en/errors.php` (new base folder `lang/`, question 9).
- `routes/api.php` registered in `bootstrap/app.php` with `api:` and `apiPrefix: 'api/v1'`, **without** `php artisan install:api` (it installs Sanctum: a dependency change that belongs to P1-C1).

### Behaviour

- Write chain: not applied here (P2-D2); the catalogue and the exception are the tools P1-C1, P2-D2, P2-D4 and P2-D5 will throw.
- Transactions, locks, audit rows: none in this task. Note for P2-D3: refusals are audited by the guard that throws them, not by the renderer.
- Licence mode: no guard (DEC-54); `LICENSE_READ_ONLY` and `PLAN_LIMIT_EXCEEDED` are catalogue entries only.
- Events and messages: none.
