## 1. What is asked

Port Authority Staff correct a vessel's particulars at any time; the change is saved with history (roadmap), which is the audit log.

**Done when** (each line is checkable by a test or a demo):

- [ ] `PUT /vessels/{vessel}` changes `name`, `vessel_type_id`, `loa`, `beam`, `max_draft`, `net_tonnage`, `moulded_depth`; a field that is not sent keeps its value.
- [ ] `imo_number` is refused (422).
- [ ] `call_sign` and `flag_state` are accepted only while the stored value is empty; another value after that is 422. The same value again changes nothing.
- [ ] Invalid values are 422, with the database CHECKs enforced first: sizes above 0, `beam` below `loa` (also when only one of the two is sent), the column limits.
- [ ] Only `PORT_STAFF` writes; every update sends `version` (409 when stale) and is audited with old and new values in the same transaction.
- [ ] `GET /vessels/{vessel}` returns the vessel with its `version`.
- [ ] OpenAPI and PortHub copy; Pint, Spectral and the full suite pass.

**Out of scope:** creating a vessel (`findOrCreateByImo`, P3-G1 and BAPLIE commit) · a vessel list or search · the container list on P-33 (P3-H4) · recommendation regeneration (sequence 2.8 has none).

## 3. Design

| Method and path | Ability | Request | Success | Errors |
| --- | --- | --- | --- | --- |
| `GET /vessels/{vessel}` | `port-state.read` | | 200 | 401 · 403 · 404 |
| `PUT /vessels/{vessel}` | `baplie.manage` + `version.token:vessel` | partial + `version` | 200 | 401 · 403 · 404 · 409 · 422 |

- Code in `MasterData`, which holds the `Vessel` model, so `Berthing` (P3-G1) and `Baplie` can use it.
- The GET exists because a client needs `version` before it can edit, and no endpoint returns a vessel yet. **Inferred.**
- `baplie.manage`: sequence 2.8 puts the edit in "Port API (BAPLIE)" and the task is in package H. Both candidate abilities belong to the same single role. **Inferred.**
- Transaction: `lockAndAssert` the vessel, check the two AI-filled columns against the locked row, apply, check `beam < loa`, save, audit.
- Events: none (`ResourceKind` has no vessel; CT-10 lists berth, tug and pilot).
- Migration: none.
- OpenAPI 1.15.0: P2-F1 and P2-F6 use 1.13.0 and 1.14.0 on branches not merged yet.
