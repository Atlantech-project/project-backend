## 1. What is asked

"Let the Port Admin browse the audit log and filter it, including the change history of master data. Done when any change can be traced to who, what and when." (`roadmap/roadmap-tasks.json:716-724`; task row `backend/atlantech_backend_tasks.md:95`). FR-MD-16 (`requirements/Functional Requirements.md:193`): "The Port Admin browses the full port audit log, filtered by entity, actor and dates, with before and after values. Master-data history is the audit log filtered by entity." Port Admin = `PORT_GM` (`requirements/Users & Actors.md:22`).

**Done when:**

- [ ] `GET /api/v1/audit-logs` returns a page of audit rows, newest first (`occurred_at` then `id` descending), each with its actor, entity, action, `before_state`, `after_state` and `occurred_at`.
- [ ] Filters `entity_type`, `entity_id`, `actor_id`, `action`, `from`, `to` and the actor text search `q` work alone and together; master-data history is `entity_type=<table>&entity_id=<id>`.
- [ ] Bad filters answer 422 `VALIDATION_FAILED` (unknown `action`, naive datetime, `from` after `to`, `per_page` out of range).
- [ ] The route declares `ability:audit.read`; 401 for a guest. The 403 for every other role is proven once P2-D1 is merged (section 7).
- [ ] Reading is allowed in READ_ONLY and SETUP licence modes (it changes nothing).
- [ ] OpenAPI describes the endpoint (minor version bump), the drift test passes, Spectral passes.

**Out of scope:** writing audit rows (P2-D3) · the role matrix and `audit.read` itself (P2-D1) · the P-29 screen (FE-050) · export, and the SaaS `platform_audit_log` browsing (P7-T2) · the readiness pack line (the pack for the feature's FRR, BE-PK2 to BE-PK7).

## 3. Design

### Endpoints

| Method and path | Role(s) and scope | Request | Success | Errors (code) |
| --- | --- | --- | --- | --- |
| `GET /api/v1/audit-logs` | `PORT_GM` (`ability:audit.read`), whole port | Query: `page`, `per_page` (default 25, max 100); `entity_type` (string, max 60); `entity_id` (integer ≥ 1); `actor_id` (integer ≥ 1); `action` (`CREATE`, `UPDATE`, `DELETE`, `STATUS_CHANGE`, `SAFETY_EXCEPTION`, `REJECTED_ATTEMPT`); `from`, `to` (ISO 8601 with `Z` or offset, `from` ≤ `to`, inclusive); `q` (1 to 100 characters, matches the actor's username or name, case-insensitive substring) | 200 `{data: [AuditLogEntry], meta: {page, per_page, total}}` | 401 `UNAUTHENTICATED` · 403 `FORBIDDEN` · 403 `PASSWORD_CHANGE_REQUIRED` · 403 `ACCOUNT_DISABLED` · 422 `VALIDATION_FAILED` |

`AuditLogEntry`: `id`, `actor` (`{id, name, username}` or `null` for the system / a worker), `entity_type`, `entity_id` (nullable), `action`, `before_state` (object or null), `after_state` (object or null), `occurred_at` (UTC ISO 8601). The role of the actor is not stored in `audit_logs`, so it is not returned.

### Data

- Reads `audit_logs` (Backend-only table, CT-15) and `users` (id, name, username, joined for the actor). No writes, no migration. Indexes used: `idx_al_entity`, `idx_al_time`, `fk_al_user`.
- Rows of a deleted user keep `actor_id` through the foreign key, so the join is a left join.
- Ordering `occurred_at desc, id desc` is stated in the query (PageRequest needs it).
- Rules in code: `from <= to`; `q` has its `%` and `_` escaped.

### Behaviour

- Write chain: not applicable (read). Order: auth · password gate · ability (`audit.read`, arrives with P2-D1) · validation.
- Transaction / locks: none. Audit rows: none (a read is not audited; a refused read is audited by the D1 middleware as `REJECTED_ATTEMPT`).
- Licence mode: allowed in READ_ONLY and SETUP (GET).
- Events and messages: none.

## 6. Impact on other backend work

- P2-D1 gives `audit.read` to `PORT_GM` only; if its matrix does not define `audit.read` the route has no one who can open it.
- Later write endpoints add master-data history for free: they write audit rows with `entity_type` = table name (P2-D3), and this endpoint filters them. A table renamed later would split its history.
- Rows written by `rejectedAttempt` have `entity_type = 'users'` and `entity_id` NULL or the actor, so `entity_type=users` mixes user history with refusals; use `action` to separate them.
