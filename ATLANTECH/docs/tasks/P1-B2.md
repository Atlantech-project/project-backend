## 1. What is asked

Review the migrations P1-B1 generated for the 45 tables of class diagrams 2A (access, marine resources, terminals and berths, safety constraints) and 2B (cargo and containers, storage, container yard, equipment and productivity) against the database design: names, types, keys and relations. Fix anything that does not match. The roadmap's "done when" is "the reviewed group is merged" (`roadmap/roadmap-tasks.json:504-512`).

The review itself was done during planning (2026-10-28) by comparing the live `atlantech` database (MySQL 8.4, `information_schema`) with the agreed SQL and the two diagrams. Result: 37 of 45 tables have no difference; the findings are in section 3 and the decisions they need in section 8.

**Tables in scope (45):**

- 2A (21): `port_profiles`, `port_settings`, `navigation_channels`, `channel_waypoints`, `organization_units`, `users`, `user_role_assignments`, `user_devices`, `audit_logs`, `pilot_profiles`, `pilot_rank_limits`, `pilot_schedules`, `port_shifts`, `tug_master_profiles`, `tug_master_schedules`, `tugboats`, `terminals`, `berths`, `berth_terminals`, `constraint_types`, `safety_constraints`.
- 2B (24): `cargo_types`, `imdg_classes`, `terminal_cargo_types`, `container_size_types`, `containers`, `storage_types`, `storage_facilities`, `tank_details`, `warehouse_details`, `storage_facility_cargo_compatibilities`, `storage_movements`, `yard_zone_types`, `yard_zones`, `reefer_zone_details`, `dg_zone_allowed_classes`, `oog_zone_details`, `yard_blocks`, `yard_slots`, `equipment_categories`, `capability_types`, `equipment`, `equipment_capabilities`, `equipment_cargo_compatibilities`, `terminal_productivity_profiles`.

**Done when** (each line is checkable by a test or a demo):

- [ ] Every finding in section 3 marked "fix" is fixed in the migrations, and `php artisan migrate:fresh` runs clean on an empty MySQL 8.4 database.
- [ ] `user_devices` FK is named `fk_device_user` (M1).
- [ ] `organization_units.single_key` is signed `bigint` (M2, answer 2) and `port_profiles.id` is `BIGINT UNSIGNED` with default 1 and `chk_port_profile_singleton` kept (C2, answer 3).
- [ ] `updated_at DATETIME(6)` (version token) is on `pilot_profiles`, `tug_master_profiles`, `pilot_rank_limits` and `yard_slots` (C4, answer 4), and a schema test lists them with the 12 P1-B1 tables.
- [ ] Schema tests cover the fixes (FK name, column types, `updated_at` list) and fail if a fix is undone.
- [ ] `contracts/db/schema.sql` regenerated with `composer contracts:schema` and published on a PortHub branch (CT-17 §5).
- [ ] A diagram and contract follow-up list (section 5) is written for the documents' owners: diagram 2A/2B patches, CT-17 minor-version notes.
- [ ] `php artisan test` passes and Pint is clean.
- [ ] The PR carries `ai-impact` and has one AI Team approval (CT-17 §6: 43 of the 45 tables are read by workers, `containers` is written by `w_edi`).

**Out of scope:** the request, BAPLIE, Part 1, Part 2, plan, execution and learning tables (P1-B3) · CHECK-constraint tests beyond what this task changes (P1-B4) · Eloquent models and PHP enums for the status columns (P1-B5) · seed rows (P1-B6, CT-18) · a source for `min_app_version` (P1-C5 / P1-C3, see section 7) · enforcing "a berth has at least one terminal" (backend rule, the master-data task that writes berths) · editing the diagram and contract documents themselves (their owners, from the list in section 5).
