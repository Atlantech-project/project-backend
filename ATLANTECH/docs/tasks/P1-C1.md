## 1. What is asked

Office staff sign in on the web dashboard with `username` and password after the Sanctum CSRF cookie exchange, and get back their profile: id, name, the one active role, terminal scope and the `must_change_password` flag. Missing fields answer 422, wrong credentials 401, a deactivated account 403 `ACCOUNT_DISABLED`. Roadmap done-when: "the web sign-in works end to end with the agreed identifier (DEC-35)" (`roadmap/roadmap-tasks.json:544`).

**Done when** (each line is checkable by a test or a demo):

- [x] `laravel/sanctum` is installed with `composer require laravel/sanctum` (no `install:api`); the API uses Sanctum's stateful SPA authentication (`statefulApi()`), and `GET /sanctum/csrf-cookie` sets the `XSRF-TOKEN` cookie.
- [x] Stateful domains (`SANCTUM_STATEFUL_DOMAINS`) and CORS origins come from `.env` (dev `localhost:5173`, `atlantech.test`), with `supports_credentials` true.
- [x] `POST /api/v1/auth/login` with `{username, password}` signs the user in: a new session id (no fixation), 200 with `{id, name, role, terminal_ids, must_change_password}`.
- [x] The username is matched as `strtolower(trim($input))`, so `Staff.Ahmed ` signs in as `staff.ahmed`.
- [x] Missing or invalid fields → 422 `VALIDATION_FAILED` with `errors` per field.
- [x] Unknown username or wrong password → 401 `UNAUTHENTICATED`, the same answer for both; a `REJECTED_ATTEMPT` audit row with `actor_id` and `entity_id` NULL and `after_state` `{route, code, reason, username}`, never the password (N6).
- [x] Correct password but `is_active` = 0 → 403 `ACCOUNT_DISABLED`, no session, audited the same way.
- [x] More than 5 attempts per minute per username + IP, or 20 per minute per IP → 429 `TOO_MANY_ATTEMPTS` with `Retry-After`, thrown as `ApiProblemException`, never `abort(429)` (Q3).
- [x] A POST without a valid XSRF token → 419 `SESSION_EXPIRED` (new `ErrorCode` case, `lang/en/errors.php`, `ProblemRenderer::CODE_BY_STATUS`, OpenAPI response `SessionExpired`, CT-01 row) (N4).
- [x] `must_change_password` = 1 still signs in (200, flag `true`); the gate itself is P1-C2.
- [x] `role` is the SQL value of the active assignment (`PORT_STAFF`, not CT-03's `PORT_AUTHORITY_STAFF`, Q6); `terminal_ids` is `[terminal_id]` for a TERMINAL unit and `[]` otherwise; a user with no active role gets 200 with `role: null`, `terminal_ids: []` (N2).
- [x] `GET /api/v1/auth/me` returns the same profile with the session cookie; 401 as a guest (N1).
- [x] The session cookie is `atlantech_session` (default in `config/session.php`, `SESSION_COOKIE` in `.env.example`), `APP_NAME=ATLANTECH`, and `cookieAuth.name` matches it (`OpenApiDriftTest`) (N3).
- [x] The web session lasts 120 minutes idle (Q1).
- [x] A sign-in from an origin that is not stateful (no session) → 400 `BAD_REQUEST`, before the credentials: no throttle hit, no audit row (review 1).
- [x] No audit row for a successful sign-in (Q10); `password_reset_tokens` and `schema.sql` unchanged (Q9).
- [ ] Every new route is in `openapi/port-api.yaml` (`info.version` 0.2.0, Spectral rules `oas3-unused-component` and `openapi-tags` back on); `composer contracts:openapi` run on a PortHub branch for a paired PortHub PR. *(Done except: `oas3-unused-component` kept off, approved by Marwan 2026-10-30 until the shared components are used; PortHub PR not opened yet.)*
- [ ] Pint clean; full Pest suite green, including `ModuleArchitectureTest` and `OpenApiDriftTest`; the PR into `develop` passes `pint`, `tests` and `openapi` and follows the PR template checklist (N9).

**Out of scope:** password gate and change-password (P1-C2) · mobile sign-in, `personal_access_tokens` with `revoked_at`, `user_devices` (P1-C3) · logout (P1-C4) · `GET /system/info` (P1-C5) · role policies and terminal-scope middleware for other endpoints (P2-D1) · the full write chain (P2-D2) · the audit service (P2-D3) · login lockout (post-MVP, FW-09) · `contracts/auth-web.md` (CT-03 task, N8) · removing `password_reset_tokens` (kept, Q9).

## 3. Design

### Endpoints

| Method and path | Role(s) and scope | Request | Success | Errors (code) |
| --- | --- | --- | --- | --- |
| `GET /sanctum/csrf-cookie` (Sanctum, outside `/api/v1`) | Guest | — | 204, `XSRF-TOKEN` cookie | — |
| `POST /api/v1/auth/login` | Guest | `{ "username": string 3–50, "password": string }` + `X-XSRF-TOKEN` | 200 profile (below), session cookie, new session id | 400 `BAD_REQUEST` (origin not stateful, review 1) · 422 `VALIDATION_FAILED` · 401 `UNAUTHENTICATED` · 403 `ACCOUNT_DISABLED` · 419 `SESSION_EXPIRED` · 429 `TOO_MANY_ATTEMPTS` |
| `GET /api/v1/auth/me` (N1) | Any signed-in user | session cookie | 200 profile | 401 `UNAUTHENTICATED` |

Profile body (CT-03 shape, enum value per Q6):

```json
{ "id": 41, "name": "Port Staff", "role": "PORT_STAFF", "terminal_ids": [], "must_change_password": false }
```

`role` is `null` and `terminal_ids` `[]` for a user with no active role (N2).

### Data

- Tables read: `users` (Backend), `user_role_assignments` (Backend), `organization_units` (Backend). Written: `sessions` (Laravel), `audit_logs` (insert only). No change to `users` or `user_role_assignments`, so **no `ai-impact` label** (lead, 2026-10-29).
- Migrations: none. Sanctum's `personal_access_tokens` migration is **not** published here; P1-C3 adds it with `revoked_at` (N7). `password_reset_tokens` stays as it is (Q9), so `schema.sql` (CT-17) is unchanged.
- Enums: `Role` (existing, `app/Modules/Access/Enums/Role.php`), `AuditLogAction::RejectedAttempt` (existing, Shared). New error code `ErrorCode::SessionExpired` (419, N4); no new status values (CT-21 unchanged).
- Rules enforced in code: username lowercased and trimmed before lookup (`chk_user_username_lower`); credentials checked before `is_active`, so a disabled account is only revealed to someone who knows the password; one generic 401 for unknown user and wrong password.

### Behaviour

- Write chain steps that apply: authentication only (sign-in is the entry point). Password gate, scope, app version, licence mode, version token and plan limits do not apply to `login` / `me`.
- Placement: everything in the Access module (`app/Modules/Access/Http/Controllers`, `Http/Requests`, `Http/Resources`, a `SignIn` service). Access may use only Shared (`ModuleArchitectureTest`).
- Sign-in steps: throttle check (5/min per username + IP, 20/min per IP; over the limit `ApiProblemException(ErrorCode::TooManyAttempts, headers: ['Retry-After' => …])`) → validate → `Auth::guard('web')->attempt(['username' => lower(trim), 'password' => …])` (the provider maps to `password_hash`) → `is_active` check (log out the guard again if 0) → `session()->regenerate()` → load `activeRoleAssignment.organizationUnit` → profile resource.
- Session: database driver (existing), cookie `atlantech_session` (default in `config/session.php` + `SESSION_COOKIE` in `.env.example`, `APP_NAME=ATLANTECH`, N3), 120 min idle (Q1), `same_site=lax`, `http_only=true`.
- SPA config: publish only `config/sanctum.php`; `SANCTUM_STATEFUL_DOMAINS` and CORS origins from `.env` (dev `localhost:5173`, `atlantech.test`; prod same site), `supports_credentials` true on `api/*` and `sanctum/csrf-cookie` (N5).
- CSRF: `TokenMismatchException` arrives as 419; `ProblemRenderer::CODE_BY_STATUS` maps 419 → `SESSION_EXPIRED` (N4).
- Transaction boundary and locks: the audit insert runs in its own transaction; no locks. Nothing else but the session is written.
- Audit rows: 401 and 403 only, `REJECTED_ATTEMPT`, `entity_type` `users`, `actor_id` and `entity_id` NULL, `after_state` `{route, code, reason, username}` (lowercased input, never the password). One small method `recordRejectedAttempt()` until P2-D3 delivers the audit service (N6). No row for a success (Q10), for 422 or for 429.
- Licence mode: sign-in is allowed in SETUP, FULL and READ_ONLY (423 applies to writes, not to sign-in; handoff "Request check chain").
- Events and messages: none.

## 6. Impact on other backend work

- P1-C2 adds the password gate right after this authentication and reuses the profile resource. It should also refuse a deactivated user on the next request (FR-AC-10, review 3).
- `auth/me` uses `auth:web`, because Sanctum's Bearer path needs `personal_access_tokens`, which P1-C3 adds. P1-C3 moves it to `auth:sanctum` with the table.
- P1-C3 reuses the `SignIn` service (credentials, `is_active`, audit, throttle) for mobile, adds `personal_access_tokens` with `revoked_at`, and must keep this task's web behaviour.
- P1-C4 ends the session started here.
- P2-D1 builds policies and terminal-scope middleware on `role` / `terminal_ids` as returned here.
- P2-D3 replaces the direct `AuditLog` write with the audit service; the `after_state` shape chosen in N6 should become its refusal shape.
