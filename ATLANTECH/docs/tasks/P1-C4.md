## 1. What is asked

Users sign out: the web session ends, and the tablet's token is cancelled on the server so the device can no longer act for that user (`backend/atlantech_backend_tasks.md:56`; roadmap: "Done when a signed-out session is refused everywhere"). The web part is on `develop` since P1-C2 (lead's request, 2026-10-30).

**Done when:**

- [x] `POST /api/v1/auth/logout` with a Bearer token answers 204 and sets `revoked_at` on that token (CT-04, FR-AC-08).
- [x] The token row stays; the same token then gets 401 on every signed-in route.
- [x] The user's tokens on other devices still work; the `user_devices` row is not changed (D13). A logout does not touch them. A password change is different (decision D-A, 2026-11-05, in P1-C3): it revokes the user's other mobile tokens and keeps the token of the request that made the change.
- [x] The web logout is unchanged (P1-C2 tests green).
- [x] OpenAPI 1.5.0 describes both; Pint and the full suite pass.

**Out of scope:** offline logout (the app deletes its local token, FR-AC-08) · revoking a device or all sessions (P2-E3).

## 3. Design

### Endpoints

| Method and path | Role(s) and scope | Request | Success | Errors (code) |
| --- | --- | --- | --- | --- |
| `POST /api/v1/auth/logout` | Any signed-in user | session or Bearer | 204 | 401 · 403 `ACCOUNT_DISABLED` · 419 (web) · 422 / 426 (mobile headers) |

### Data

- Writes `personal_access_tokens.revoked_at` through `PersonalAccessToken::revoke()` (P1-C3). No migration. No audit row (sign-in and sign-out are not audited, Q10).

### Behaviour

- `AuthController@logout`: a Bearer request revokes its token; a session request ends the session as before. Logout leaves the other devices' tokens alone; only a password change revokes them (P1-C3 D-A, `PasswordChangeService`).
